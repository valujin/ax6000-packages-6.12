# Проверяемые исправления сборки Linux 6.12

Оба канала применяют семь исправлений через отдельные закреплённые
[recommended manifest](../patches/firmware-6.12/recommended/manifest.json) и
[latest manifest](../patches/firmware-6.12/latest/manifest.json). Manifest хранит
SHA-256 патча и исходного/полученного файла; для нового файла исходный hash равен
`null`. Неизвестная ревизия файла отклоняется до применения.

| Патч | Причина и результат |
|---|---|
| `100` | Initramfs XZ использует один worker `-T1`; остальные параметры компрессии сохранены. |
| `110` | Шесть Open vSwitch `*-intree` вариантов поддерживают ядра не выше 5.5, но их metadata ошибочно допускает 6.12. Условие `@!LINUX_6_12` исключает только эти варианты; четыре современных варианта остаются доступны. Патч требует точный packages feed commit из manifest. |
| `120` | Vendor-патчи добавляют pressure sensors `ZTS8032` и `ZTS8232`, а generic config не задаёт их значения. При `ALL_KMODS` native `syncconfig` запрашивает ввод и останавливается с `FAIL_ON_UNCONFIGURED=1`. Явные `n` устраняют только два запроса, не меняя остальные значения. |
| `130` | Vendor Ethernet безусловно включает `mtk_eth_ptp.o`. При встроенном Ethernet и модульном PTP ядро не линкуется. Добавленный kernel patch выбирает `PTP_1588_CLOCK` вместе с драйвером при `POSIX_TIMERS`, сохраняя встроенный Ethernet, модульный вариант и dummy helpers при отключённых timers. |
| `140` | Vendor-патч PHY v1.9.2 создаёт составной модуль `aeon_as21xxx.ko`, но рецепт ожидает `as21xxx.ko`. Исправлены только `FILES` и `AUTOLOAD`; имя пакета, firmware/libphy зависимости и `CONFIG_AS21XXX_PHY` сохранены. |
| `150` | `rtl8812au-ct` дописывает MP ioctl строки через `sprintf(extra, "%s…", extra, …)`, что нарушает правила перекрытия буферов и останавливает GCC 14 с `-Werror=restrict`. Новый package patch использует `extra + strlen(extra)` для 54 таких вызовов, по примеру существующего патча `011`; форматы, аргументы и политика предупреждений сохранены. |
| `160` | Stock `initramfs-factory.ubi` должен помещаться в раздел `ubi_kernel` размером 30 MiB. Нативный `check-size 30720k` удаляет слишком большой factory artifact; остальные layout pipelines и sysupgrade сохранены. |

Патч `130` добавляется как
`target/linux/mediatek/patches-6.12/999-zzz-5400-net-mediatek-select-reachable-ptp-clock.patch`,
после исходных vendor Ethernet/Kconfig патчей обоих закреплённых деревьев.
`NET` уже требуется через `NETDEVICES`; условие `POSIX_TIMERS` покрывает вторую
зависимость PTP и исключает некорректный `select` при отключённых timers.

Нативный kernel `conf` Linux 6.12.108 проверен на отдельной копии конфигурации и
дереве из ссылок только для чтения. Для `120` результат `olddefconfig` до и после
исправления совпал побайтно. Для `130` изменились ровно `PTP_1588_CLOCK`,
`PTP_1588_CLOCK_OPTIONAL` и `PPS`: `m` → `y`; остальные значения совпали.
Kconfig MediaTek реконструирован из upstream 6.12.108/6.12.112 и vendor-патчей
обоих исходных commits: итоговые файлы совпали побайтно. Регрессионный тест
дополнительно покрывает Ethernet `y`/`m`, отсутствие timers и отсутствие `NET`.

Для `140` исходный recipe и vendor-патч переименования совпадают побайтно в
обоих source commits. Реальный модуль из сборки recommended имеет ELF AArch64,
`name=aeon_as21xxx` и `vermagic=6.12.108 SMP mod_unload aarch64`.
Регрессионный тест исполняет закреплённые native GNU Make `KernelPackage`
правила: прежний `FILES` завершается ошибкой, исправленный устанавливает файл
модуля и `etc/modules.d/18-phy-aeonsemi-as21xxx` со строкой `aeon_as21xxx`.
Этот packaging patch не меняет исходники или конфигурацию ядра.

Для `150` оба source commits используют одинаковый recipe с драйвером
`9b2b203a217e1320602a0eb07c338a1bfca0f5a6`. Файл `ioctl_linux.c` из проверенного
архива совпал побайтно с подготовленным исходником после штатных package patches.
Новый патч добавляется в `package/kernel/rtl8812au-ct/patches/120-fix-mp-ioctl-sprintf-self-append.patch`.
Тест компилирует все 54 изменённых вызова, включая условные Bluetooth-ветки,
с `-Werror=restrict`. Прежние вызовы отклоняются, исправленные дают 432 результата,
совпадающих с независимым форматированием hex/decimal значений, пробелов, табов
и переводов строки для пустого буфера и существующего префикса.
Изменяется только каталог patches внешнего package: штатный `STAMP_PREPARED`
заново готовит этот драйвер; патчи, конфигурация и build context ядра не меняются.

Исторический static recipe Tailscale r2 сохраняет официальные бинарники:
`RSTRIP:=:` отключает post-install strip только для этого пакета. Штатный
Golang recipe тоже обходит `sstrip`, поскольку он повреждает section headers
Go ELF. Для уже подготовленного официального release archive повторная обработка
не нужна. Revision `r2` позволяет обновить прежний `r1`; init/config wrappers,
зависимости, версия и SHA-256 официального архива остаются прежними.
Регрессионный тест исполняет native install/strip Make-последовательность с
`CONFIG_USE_SSTRIP=y`: контрольный вариант вызывает `sstrip -z`, новый сохраняет
оба ELF файла побайтно без запуска strip. Общая настройка strip и ядро сохранены.

Новый source-multicall/UPX recipe r3 использует один ARM64 ELF и две ссылки,
также с `RSTRIP:=:`: native strip не должен менять уже упакованный ELF.
Реальная SDK-сборка APK/IPK 39702777128 и отдельные UPX/ARM64 QEMU проверки
прошли; APK — 11 921 395 байт, Installed-Size 12 225 198 байт. Init/config,
зависимости, providers и сохранение состояния сверены с исходным r2.
Это userspace-изменение не меняет нативный kernel context, прошивку или SDK.
Подписанный REC Release r3 опубликован, Pages-активация 39711729943 и свежая
проверка изменённых файлов по HTTPS успешны; остальной банк не скачивался заново. [Подробности](tailscale-sdk-acceptance.md).

Stock factory artifact может отсутствовать после проверки размера: это
обязательный отказ от слишком большого файла, а не причина обходить лимит.
Отдельный RAM initramfs допускается как файл загрузки в RAM/TFTP; его размер
не разрешает записывать его в stock `ubi_kernel`. Размер и payload sysupgrade
проверяются отдельно.

При resume после добавления `160` нужно записать hashes и удалить прежние
stock factory файлы в `BIN_DIR`, `KDIR/tmp`, соответствующий image JSON и
`BIN_DIR/profiles.json`, затем выполнить штатную генерацию изображений/каталога.
Нативный ignored `cp` не удаляет старый BIN artifact, а overview generator
сохраняет записи прежнего каталога при той же revision. Регрессионный тест
воспроизводит оба эффекта и проверяет чистую регенерацию; ручная миграция
подготовленного build выполняет эту очистку отдельно. Production `--resume`
теперь выполняет тот же ограниченный reset после `verify`, перед `world`, и
записывает hashes удалённых файлов в уникальный `work/image-cache-reset.*/receipt.json`
вне source. Канал, actual source HEAD, пути и receipt проверяются до удаления;
файлы других layouts, конфигурация и модули сохраняются. Для новых сборок старых
артефактов нет. Boundary-тест проверяет 30 MiB − 1, ровно 30 MiB и 30 MiB + 1.

Штатный расчёт `.vermagic` по `.config.set` сохраняется. После полной сборки
проверяется окончательный kernel context из шести файлов в SDK; hash или
зависимости kernel IPK вручную не изменяются. Добавление kernel patch вызывает
штатный `Kernel/Autoclean` для дерева ядра; собранный toolchain сохраняется.
Эти проверки подтверждают конфигурацию, а готовые образы, SDK compile и работу
на роутере нужно проверять отдельно.
