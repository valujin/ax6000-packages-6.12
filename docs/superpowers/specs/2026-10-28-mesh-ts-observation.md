# Local traffic-separation observation contract

`mapd` writes `/var/run/ax6000-mesh-ts.json` after receiving a validated MAP R2 local traffic-separation setting from 1905. It writes a private temporary file, flushes it, and atomically renames it into place with mode 0600. Invalid or incomplete input, write failures, and a new 1905 connection remove the observation. A consumer must tolerate the file disappearing between operations and must never interpret absence as permission to place guest traffic on the primary network.

Schema 2 is a JSON object with `schema` (integer 2), `boot_id` (kernel UUID), `producer_pid` (mapd PID), `producer_start_ticks` (Linux `/proc/<pid>/stat` field 22), `connection_generation` (positive per-process 1905 connection counter), `controller_alid` (current controller topology MAC), `monotonic_ms` (observation time), `sequence` (positive per-process event counter), `primary_vid` (1–4094), `primary_pcp` (0–7), `allowed_vids` (deduplicated VID array, at most 48), and `fh` (at most 48 objects containing a unique unicast `bssid` and its `vid`). Every FH VID must be the primary VID or appear in `allowed_vids`. No SSIDs, passwords, or keys are exported.

The exporter deletes the file before each 1905 connection attempt, at connection close, and on detected receive/pending errors. A successful connection advances `connection_generation` and permits export. Export also requires a known unicast controller ALID: the local ALID for a controller, or the controller in mapd's current in-network topology for an agent. If unavailable or invalid, export fails closed and removes the file. The topology ALID describes current topology; it does not prove the event's authenticated origin. An event arriving before topology discovers the controller is discarded, and a later valid TS event is required to publish. The consumer must verify boot identity, live mapd PID and process start ticks, current 1905 daemon identity and connection health, expected controller ALID, and generation/sequence ordering. A new generation or producer invalidates all previous observations. The process counter resets on restart; `(boot_id, producer_pid, producer_start_ticks, connection_generation)` identifies a connection instance. Abrupt termination may leave a file, so file presence alone never proves liveness.

The file describes the 1905 event, not an acknowledgement that WAPP, the wireless driver, bridge VLAN filtering, or firewall rules have applied it. A reconciler must independently validate the schema, bounds, MAC addresses, boot identity and current daemon/connection lifecycle, map each BSSID to a current local fronthaul interface, and verify the resulting bridge state before declaring readiness. It must quarantine an unknown, changed or unverified guest port, and keep guest VLANs isolated from the primary management network. No observation grants access to unlisted VLANs, and an empty FH list does not establish that any port is safe. On file disappearance or invalid data, block guest forwarding while preserving management and request a fresh valid event. This interface alone does not provision VLANs or synchronize controller firewall/DHCP policy.

The exporter is event driven rather than a heartbeat: an unchanged observation may remain valid while the same connection is healthy. A reconciler must watch daemon/connection lifecycle and must not use age alone as proof of liveness. 1905 regenerates the event after local BSS changes and, in managed mode, republishes its current policy after a successful mapd subscription. Controller local WTS renew updates the 1905 radio/BSS records before emitting the same event; those records are proposed configuration and are not a driver-application acknowledgement. The reconciler must revalidate interface identities and VLAN membership after each change and after driver restarts. Until native build and two-node packet tests demonstrate tagged forwarding and isolation, this contract must not be presented as completed guest-network support.

Managed mode is opt-in via `AX6000_MESH_LINUX_TS=1` in both 1905 and mapd. It suppresses vendor TS data-plane mutations and WAPP TS delivery. A 4095 no-TS clear removes the observation; the Linux reconciler must quarantine guest forwarding when the file disappears and independently verify the resulting bridge state. Ordinary vendor mode retains its prior WAPP behavior. No existing pre-attach quarantine acknowledgement has been established, so managed mode must remain disabled until the reconciler and provisioning lifecycle enforce it. Production policy-request serialization includes an explicit managed clear, but a controller integration must still trigger distribution to each authenticated agent and verify convergence after network changes.
