# Controller network synchronization implementation boundary

## Implemented stable allocation

`ax6000-mesh-allocate-slots POLICY_JSON PREVIOUS_STATE_JSON` validates the normalized non-secret policy through `ax6000-mesh-plan-networks`. It reads explicit previous state, never substitutes empty state for a missing/corrupt file, and emits a proposal containing the validated BSS records with stable `slot`/`ifname`, plus a replacement `state`. Neither input is modified. No UCI, bridge, driver, daemon, credential, or network operations occur.

Previous state is `{"schema":1,"slots":[{"id":"main24","band":"2g","slot":0,"active":true}]}`. IDs are persistent globally unique UCI section identities, not SSIDs or list positions. Names may change without renumbering. Keep this state private and publish it atomically only as part of the complete provisioning transaction. A lost allocation ledger requires recovery, not automatic reinitialization. Initial empty state is an explicit `{"schema":1,"slots":[]}`.

The bounded implementation accepts requested capacity 2–4 including dedicated backhaul slot 1. This is an upper operational bound, not hardware capacity discovery; the caller must supply the smallest verified node capability. Each active band needs its original primary-network BSS in slot 0. Other client BSSs receive 2 then 3. Deletion preserves an inactive tombstone; readding the same identity restores its slot, and reordering cannot renumber retained identities. Slot 0 cannot turn into a guest. Identity band changes, slot collisions, capacity reductions excluding tombstones, and exhausted retained pools fail without outputting a partial plan. Multiple SSIDs may share the primary network, but only the retained primary identity owns slot 0. No automatic tombstone collection exists: releasing a slot requires evidence that every enrolled node, including an offline node on rejoin, cannot restore the previous occupant.

## Required next integration, in dependency order

1. Preserve the baseline wireless/network/firewall/DAT snapshots and owned-section expectations. Extend ownership beyond SSID1/SSID2 without changing unrelated slots. Preallocate actual AP capacity on agents; constants permitting 16 do not establish usable slots.
2. Establish explicit transport ownership per node. Dedicated `wan` may be an agent wired trunk only after the AP-mode transaction claims it; arbitrary LAN/access ports must not become guest trunks. Wireless transport must enumerate actual owned BH AP and APCLI interfaces and revalidate identities after reconnect. Keep management untagged, use primary PVID 1 only if conflict-free, and carry explicit guest VIDs tagged. Bridge VLAN filtering and all primary memberships must be staged without readdressing management. Netifd must preserve these settings across reload/reboot. No unknown port receives a primary default PVID.
3. Enforce quarantine before bridge attachment. In the mtwifi ucode netifd script, `netifd.set_vif()` only reports names using `CMD_SET_DATA`; `cfg.setup(data, all_devs)` brings driver interfaces up; `netifd.set_up()` sends `CMD_UP`, allowing netifd to attach them. A managed-mode mandatory gate belongs before `set_up()`, and guest/unknown UCI interfaces must already have no `network=lan` before `cfg.setup()`. Failure/missing helper aborts managed setup. Driver per-BSS `NoForwarding=1` must precede guest availability; bridge blocking does not prevent driver intra-BSS forwarding. A post-attach watcher alone cannot establish this invariant.
4. Generate a complete WTS profile from stable order 0,1,2,3, including identical 5GL/5GH ordering, explicit primary/guest VIDs, and supported security. Native `_1905_lib_io.c` assigns sequential matching WTS/M2 rows to BSS priority order and caps count to reported BSS capacity. **A sparse allocation cannot simply omit a deleted row.** Missing slot2 with active slot3 shifts credentials to the wrong BSS unless a verified inert tombstone row/slot remains or native exact-slot assignment is implemented. Both controller local assignment and agent received-M2 assignment need coverage.
5. Enforce a conservative transportable guest contract: no guest-to-primary forwarding, driver per-BSS client isolation enabled, and exact VID identity. Reject unsupported enterprise/FT, custom ACL, policy routing, cross-node client-isolation promises, or firewall semantics not demonstrably enforced by the controller gateway and local dataplane. WSC carries credentials/security; SSID→VID does not carry firewall or isolation policy. Do not interpret native control receipt as authenticated evidence of those omitted properties.
6. Under Mesh operation locks, coalesce controller changes, validate the whole proposal, stage a root-only WTS/ledger/owned-config generation, quarantine affected ports, publish, distribute policy and invoke `mapd_cli /tmp/mapd_ctrl renew`. Existing committed `prepare()` deliberately preserves old WTS; it must not serve as change detection. Detect password changes too without exposing keys in status/argv. Avoid holding the radio lock across `wifi up`.
7. Track desired and verified applied generation per enrolled AL MAC, keep partial/error state, retry offline peers on rejoin and daemon events. CLI exit status is only command acceptance. Verify BSS identity, VID, port flags and observed data path before lifting quarantine or advancing applied generation. Failed/unknown peers stay blocked for guest service. On failure restore the complete last safe generation while retaining unrelated user edits.

## Current source gates

Legacy enrollment remains unchanged. An already committed enrollment can enter explicit `linux_ts=1` managed mode only with a root-owned measured four-slot capability, pre-existing management-preserving VLAN filtering/default PVID zero, and staged generation validated by the controller/agent coordinator. The source netifd gate quarantines guest slots before CMD_UP. No default config enables this mode.

## Dense private WTS candidate writer

`ax6000-mesh-stage-wts POLICY STATE PRIVATE_CREDENTIALS QUARANTINE_VID NEW_OUTPUT` is the private staging helper used by the controller coordinator. It invokes the stable allocator, requires both primary BSSs and explicit four-slot capacity on both radios, and creates a new mode-0600 output without overwriting an existing path. It prints no profile or keys, publishes no live file, and invokes no renewal. Quarantine VID is supplied explicitly and checked against every planned client VID and primary VID; the caller must additionally check all existing local/trunk allocations, since the helper does not read network configuration.

Credentials schema is `{"schema":1,"backhaul_ssid":"...","backhaul_key":"...","backhaul_security":"sae","quarantine_key":"...","keys":[{"id":"main24","key":"..."}]}`. The file must be private and caller-owned. Credential JSON uses jshn's file interface so keys do not become external process arguments. Every active identity needs exactly one key; unused/duplicate identities fail. Existing PSK2/SAE BH behavior is preserved. Client modes remain planner-supported WPA2 or mixed. Guest BSSs must request isolation; this validates intent, not driver application.

Rows are dense in order FH0/BH1/FH2/FH3 for 2g/5GL/5GH. Missing slots receive hidden `AX6000-quarantine-BAND-SLOT` WPA2 placeholder credentials and the explicit quarantine VID, never the primary VID. Real client/backhaul SSIDs cannot use that namespace. The quarantine key must be independently generated and retained privately by the future transaction owner. The quarantine VID has **no CPU endpoint, DHCP service, forwarding membership, or uplink membership**. A matching native TS observation for a placeholder is never permission to unblock that slot. Reconciler must consume a generation-bound active-slot allowlist and permanently reject quarantine VID until a complete later policy replaces it. Dense placeholder rows require device-side verification before operational use; no capability or isolation result is inferred from successfully writing the text.

`tests/test_mesh_wts_stage.py` verifies dense holes before a retained slot3, identical 5GL/5GH ordering, SAE BH preservation, quarantine collisions/namespaces, guest isolation refusal, private and complete credentials, capacity refusal, literal shell punctuation, output mode/no stdout, and actual jshn argv capture without key contents.

## Implemented ownership, pre-attachment gate and explicit runtime

`ax6000-mesh-ts-own DECLARATION OBSERVATION NEW_OUTPUT` creates a private disabled ownership candidate, without changing interfaces. Declaration schema 2 has exact fields: `schema`, `bridge` (`br-lan`), `management_vid`, `quarantine_vid`, `controller_alid`, `management_ifnames`, `trunk_ifnames`, `guest_ports`, and `cpu_guest_links`. Each guest has `ifname`, `actual_bssid`, `vid`, `enabled:false`. Only slots ra2/ra3/rax2/rax3 qualify. Trunks are explicitly owned wan/ra1/rax1/apcli0/apclix0; LAN access ports cannot silently become trunks. Declaration and observation must be private root-owned files. Existing management/trunk interfaces must already be members of br-lan. Guest sysfs BSSID and observed BSSID→VID must match; management/quarantine/guest VID collisions fail.

The producer binds current boot, actual mapd PID/start ticks, actual 1905 PID/start ticks, known controller ALID and observation connection generation/sequence. Its output adds `boot_id`, random 32-hex `generation`, `daemons:{mapd:{pid,starttime},ieee1905:{pid,starttime}}`, and `observation:{connection_generation,sequence}`. It rereads process and observation identities before output. This generation must be rebuilt after any changed policy/connection/daemon identity; an old observation cannot bootstrap new daemons.

The mtwifi source patch now checks explicit `ax6000_mesh.main.linux_ts=1` before calling a mandatory `ax6000-mesh-ts-gate preflight` before driver setup, and `preattach` after driver setup but before netifd CMD_UP. Failure stops setup and suppresses the radio-ready daemon-start hook. Legacy mode does not call the gate. The gate requires committed wireless configuration with exactly four AP slots per radio: LAN FH0, LAN BH1, and isolated FH2/FH3 with no netifd network assignment. It calls reconciler `prepare`, then verifies every guest/placeholder slot down and unbridged, including slots absent from active inventory. A missing reconciler, unknown configuration, wrong bridge mode, failed command or failed readback rejects managed setup.

`ax6000-mesh-ts-runtime stage PRIVATE_OWNERSHIP` takes the runtime lock, requires VLAN filtering already enabled and bridge `default_pvid=0`, quarantines the old ownership and the proposed ownership, attaches only exact candidate guests while down, and calls reconciler `apply`/`verify` with all guests disabled. Only then does it atomically publish `/etc/ax6000-mesh/ts-ownership.json`, preserving the previous ownership file. It does not enable filtering, readdress management, create controller CPU/L3 interfaces, change DHCP/firewall policy, publish WTS, or change original Mesh configuration snapshots. Failed staging leaves affected guests down; it does not restore unverified forwarding.

`ax6000-mesh-ts-runtime monitor GENERATION` is an explicit foreground activation owner. It requires a private root-owned `/etc/ax6000-mesh/ts-dataplane-approved` file containing that exact generation, which the observation owner derives only from a separately provisioned root-private hardware capability matching the exact implementation, native binaries, ABI, driver and supported platform/topology; separately bound native transport authority is validated locally. The capability is never created by normalization or staging. The monitor verifies the disabled generation, atomically publishes enabled intent, calls reconciler apply, then polls verification with a one-second interval between completed checks. Each kernel command has its own timeout; this is not a one-second worst-case quarantine bound. Observation disappearance/change, invalid current daemon identity, altered interface/VLAN state, or a handled stop signal triggers down/quarantine. `quarantine` explicitly invokes prepare without requiring active daemon identity.

The separate `ax6000-mesh-sync` procd service supervises controller/agent policy publication and native observation consumption. Managed mode exports `AX6000_MESH_LINUX_TS=1` to both native daemons, preserving the existing backhaul-security environment. The controller normalizes existing UCI guest VLAN/firewall/DHCP ownership, publishes dense WTS plus stable ledger through a resumable journal, then requests native renewal. Agent staging creates the same bounded slot pool; native WSC supplies credentials. No SSH configuration replacement is used.

`ax6000-mesh-ts-observe` binds observed BSSID/VID pairs to actual bounded interfaces and explicit root transport authority, stages all guests disabled, then checks the externally supplied dataplane capability. On success it derives the nonce marker and starts `ax6000-mesh-ts-supervise`, whose independent process owns the runtime worker. Missing/changed native policy or capability, worker death, supervisor restart and service stop revoke forwarding. Controller desired/applied status remains `pending_unverified` for remote peers: native CLI acceptance is not a remote Linux ACK.

A separate post-commit bootstrap owner upgrades native enrollment automatically only when a validated release capability exists; it derives per-enrollment authority from genuine native topology and journals the management-preserving bridge transition. No packet-isolation or four-slot hardware acceptance is claimed by software tests. See `docs/MESH-MANAGED-ROLLOUT.md` for explicit provisioning and remaining acceptance requirements.

Validation now also executes the real ucode netifd setup function to verify preflight/driver/preattach/CMD_UP ordering and both failures; the shell gate checks unknown slots and LAN-refusal; the ownership producer checks live identity, mismatched controller/VID/BSSID, and nonce generation; and runtime tests use the actual ucode reconciler with a persisted ip/bridge model to verify disabled staging and observation-loss quarantine after explicit activation. The exact mtwifi patch preimage/postimage hashes and manifest are regenerated and checked.
