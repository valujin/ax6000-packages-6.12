# Ручная проверка прошивки 6.12 на AX6000

Обе линии имеют три разметки. Для первого испытания выбрать образ
`xiaomi,redmi-router-ax6000-stock`. `mtkuboot` и `ubootmod` требуют
соответствующей разметки и загрузчика; их образы и инструкции восстановления
нельзя применять к stock. Файлы preloader/FIP только доступны для скачивания;
автоматически они не прошиваются. Vendor-драйверы MediaTek сохранены.

Перед ручным обновлением сохранить резервную копию конфигурации, текущий образ
и доступные данные восстановления роутера. Архив настроек содержит пароли — не
публиковать его в этом репозитории. Проверить SHA256 скачанного образа по
опубликованному `SHA256SUMS` и формат образа на самом роутере:

```sh
ubus call system board
sysupgrade -T /tmp/immortalwrt-...-xiaomi_redmi-router-ax6000-stock-squashfs-sysupgrade.bin
```

`-T` только проверяет образ. Прошивка, перезагрузка и решение о сохранении старых
настроек выполняются владельцем вручную. Автоматическая сборка не проверяет
загрузку, Ethernet и Wi-Fi на физическом устройстве.

После установки проверить Wi-Fi, проводную сеть и `opkg status kernel`; затем
выполнить встроенную команду `ax6000-install-feed`. До этого источники пакетов
не подключены; доверенный публичный ключ уже включён в образ. Installer также
доступен как `scripts/install-feed.sh` в исходном репозитории. Он проверяет точный ABI и
архитектуру, фиксированный fingerprint ключа и подпись индекса, добавляет feed и
выполняет `opkg update`. Пакеты он не устанавливает.

После успешной проверки installer сохраняет исходные `/etc/opkg.conf` и все
`/etc/opkg/*.conf` вместе с их permissions в уникальном каталоге
`/etc/opkg/ax6000-feed-backup.*`; точный путь выводится как `Backup:`. Каталог
backup не загружается opkg. Затем installer отключает остальные активные
источники и оставляет ровно один matching feed, сохраняя настройки signature
checks, архитектур, destinations и существующие комментарии. Повторный запуск
не добавляет дубликат feed. Symlink-конфигурации требуют ручного разбора:
installer откажется до изменения ключей или feeds.

У opkg нет приоритета источников. Moving official feeds могут предложить более
новую версию модуля с другим ABI или несовместимые библиотеки; поэтому
подключать их параллельно matching feed не следует. Если `opkg update` завершится
ошибкой, installer не сообщит об успехе; matching feed и backup останутся для
проверки. При необходимости исходные configs можно восстановить вручную из
подкаталога `original` указанного backup.

Для прошивки 6.6.95 новые kmods несовместимы. Новая прошивка и её
модули считаются одним набором; не менять зависимости kernel принудительно.

Линия `latest` предназначена для отдельного тестового роутера: upstream
сообщает о регрессиях аппаратного NAT на NETSYS_V2. Успешная сборка не
доказывает, что они не влияют на MT7986 при работе в качестве роутера.
Сначала проверить WAN/LAN, Wi-Fi, NAT, VPN, PBR и MultiWAN без переноса
производственного трафика. Linux 6.18 в этой серии не собирается.
