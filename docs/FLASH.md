# Ручная установка и проверка Mesh на Redmi AX6000

Для двух роутеров опубликовано поколение `redmi-ax6000-612-recommended-ae65e1de6997-2c5f0d54ae97` с ImmortalWrt 25.12 / Linux 6.12, пакетами APK и MediaTek EasyMesh. Возьмите оба образа из [одного подписанного Release](https://github.com/valujin/ax6000-packages-6.12/releases/tag/firmware-redmi-ax6000-612-recommended-ae65e1de6997-2c5f0d54ae97), выбрав текущую разметку каждого роутера. Соответствующий feed recommended активирован; ссылки на каталог и репозиторий находятся в [README](../README.md).

Развивается только recommended. Прежние Releases latest и Linux 6.6 сохранены для истории. Новая прошивка собрана без ASU; Tailscale остаётся отдельным APK. Установка выполняется владельцем вручную.

## Выбор образа

Проверьте разметку **каждого** роутера: выполните `ubus call system board` и выберите файл для указанного устройства. Для первого испытания на штатной разметке используется `stock`.

| Разметка роутера | Файл обновления установленной совместимой системы |
| --- | --- |
| `xiaomi,redmi-router-ax6000-stock` | `*-stock-squashfs-sysupgrade.bin` |
| `xiaomi,redmi-router-ax6000-mtkuboot` | `*-mtkuboot-squashfs-sysupgrade.bin` |
| `xiaomi,redmi-router-ax6000-ubootmod` | `*-ubootmod-squashfs-sysupgrade.itb` |

Образы этих разметок не взаимозаменяемы; переход на другой загрузчик и разметку — отдельная процедура.

Для stock также выпускаются два других типа файлов. `*-stock-initramfs-factory.ubi` — нативный UBI с временной initramfs для подходящей процедуры factory/recovery. `*-stock-initramfs-kernel.bin` — FIT для загрузки временной системы в RAM. Ни один из них не заменяет stock sysupgrade: после временной загрузки постоянная установка выполняется отдельно по процедуре используемого загрузчика.

## Перед ручным обновлением

Сохраните конфигурацию и данные восстановления каждого роутера. Сверьте SHA-256 выбранного файла с контрольной суммой в **том же новом Release**, к которому относится подписанный каталог. Не используйте суммы или SDK предыдущего поколения.

Скопируйте выбранный sysupgrade-файл на соответствующий роутер и проверьте его без записи flash. В примере замените путь на имя своего файла:

```sh
IMAGE=/tmp/имя-выбранного-sysupgrade-файла
sha256sum "$IMAGE"
sysupgrade -T "$IMAGE"
```

Для stock sysupgrade опубликованного поколения SHA-256: `699bbc26d5e60f3075f49ebd381323717bc8f7db7065307e86d2ede6be85e49a`. Сопоставьте вывод `sha256sum` с суммой опубликованного Release. Продолжайте ручную установку только после успешного `sysupgrade -T`; эта команда сама не прошивает устройство. Процедура стенда и восстановления описана в [TESTBENCH.md](TESTBENCH.md).

## После установки

Проверьте доступ к каждому роутеру по Ethernet и Wi-Fi. На самом роутере от root проверьте версию установленного ядра и подключите соответствующий этому поколению подписанный APK feed:

```sh
apk --no-network query --installed --format json --fields name,version kernel
ax6000-install-feed
apk update
```

`ax6000-install-feed` проверяет совместимость feed и сохраняет прежние настройки; сам он не устанавливает дополнительные пакеты. Подробности — в [README](../README.md#пакеты).

## Первое испытание двух узлов

Mesh по умолчанию выключен. Оба AX6000 должны работать на новой согласованной прошивке: одной установки APK поверх старого образа недостаточно. Первую настройку удобнее выполнять по кабелю.

1. На основном роутере используйте по одной включённой видимой точке доступа в LAN на 2,4 и 5 ГГц. Поддерживаются WPA2-PSK и смешанный WPA2/WPA3 (`sae-mixed`); имена и пароли диапазонов могут различаться. Отключите отдельную настройку 802.11r. Нужен стандартный `br-lan` без VLAN-фильтрации; удалите дополнительные и отключённые точки доступа.
2. В LuCI откройте **Сеть → MediaTek Mesh**. На основном роутере выберите «Основной роутер (контроллер)» и нажмите «Включить Mesh». Его клиентские имена и пароли сохраняются; для backhaul используется отдельная сеть.
3. На дополнительном роутере выберите «Дополнительный узел (агент)» и способ соединения. Для Ethernet подключите **WAN дополнительного узла к LAN основного роутера**, затем начните подключение узла. Для Wi-Fi расположите роутеры рядом, нажмите «Добавить узел» на основном роутере и начните подключение дополнительного узла в открытом окне сопряжения.
4. Дополнительный узел автоматически получает настройки Wi-Fi и адрес управления; его DHCP-сервер и IPv6-сервисы LAN отключаются на время работы Mesh. Страница узла может отключиться при смене адреса: проверьте список DHCP-аренд основного роутера для поиска нового адреса. Страница Mesh показывает идентификатор узла, но пока не его адрес; идентификатор не обязательно совпадает с MAC-адресом DHCP-аренды. При неудаче узел пытается восстановить прежние настройки; проверьте сообщение об ошибке и при необходимости повторите восстановление. Таймер начального подключения — 360 секунд; последующее восстановление выполняется отдельно и может занять дополнительное время, включая до 270 секунд на восстановление радиомодулей.
5. Проверьте получение адреса клиентом, доступ через дополнительный узел, повторное соединение после перезагрузки и переход клиента между узлами. Ответ службы на странице сам по себе не подтверждает соединение или роуминг.

Кнопка «Выключить Mesh и восстановить настройки» возвращает сохранённые настройки сети и Wi-Fi; при конфликте с последующими ручными изменениями страница сообщает об этом. Подробные ограничения и порядок настройки — в [MEDIATEK-MESH.md](MEDIATEK-MESH.md). На финальном образе одного stock AX6000 проверены загрузка, Argon, активность обоих радиомодулей со смешанным WPA2/WPA3, WAN и DNS, включение контроллера, отображение окна PBC и выключение с восстановлением. На финальном образе этого же устройства проверено восстановление беспроводного агента при отсутствии контроллера: вернулись исходный LAN-адрес, оба радиомодуля, DHCP и IPv6-службы. Клиентский трафик на финальном образе и испытания двух узлов, включая сопряжение и роуминг, ещё предстоят.
