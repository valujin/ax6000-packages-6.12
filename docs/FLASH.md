# Ручная проверка прошивки 6.12 на AX6000

Recommended: [новый Release](https://github.com/valujin/ax6000-packages-6.12/releases/tag/firmware-redmi-ax6000-612-recommended-ae65e1de6997-6ef19743b104),
[SHA256SUMS](https://github.com/valujin/ax6000-packages-6.12/releases/download/firmware-redmi-ax6000-612-recommended-ae65e1de6997-6ef19743b104/SHA256SUMS).
Latest: [новый Release](https://github.com/valujin/ax6000-packages-6.12/releases/tag/firmware-redmi-ax6000-612-latest-a99b0888b88f-0b1249707848),
[SHA256SUMS](https://github.com/valujin/ax6000-packages-6.12/releases/download/firmware-redmi-ax6000-612-latest-a99b0888b88f-0b1249707848/SHA256SUMS).

Обе линии собирают stock, mtkuboot и ubootmod. Для первого испытания выбрать
`xiaomi,redmi-router-ax6000-stock` и recommended. Другие разметки требуют
своего загрузчика и разделов; их файлы и инструкции нельзя применять к stock.
Preloader/FIP доступны только как отдельные файлы: автоматической записи
загрузчика или изменения разметки здесь нет.

## Выбрать правильный файл stock

| Файл | Формат и использование |
| --- | --- |
| `*-stock-initramfs-factory.ubi` | Нативный UBI для подходящей stock factory/recovery процедуры; recommended **17 825 792 байта**, latest **17 825 792 байт**, лимит kernel **30 MiB** |
| `*-stock-initramfs-kernel.bin` | FIT для RAM-загрузки по подходящей процедуре; не заменяет UBI для прямой записи в kernel |
| `*-stock-squashfs-sysupgrade.bin` | Обновление уже установленной совместимой OpenWrt/ImmortalWrt с stock layout |

Factory UBI содержит временный initramfs. Дальнейшая установка постоянной
прошивки выполняется владельцем отдельно по процедуре его загрузчика.
Sysupgrade не является factory-образом для интерфейса Xiaomi. Размер и
структура UBI проверены программно; запуск на физическом роутере не проверялся.

## Проверка перед установкой

Сохранить конфигурацию, текущий образ и доступные данные восстановления.
Архив настроек содержит секреты; не публиковать его. Проверить SHA256 файла
по каталогу и контрольным суммам **того же нового Release**, а не по суммам
предыдущего поколения. Прошивка и SDK должны относиться к одному build ID.

На роутере проверить модель/разметку и формат **sysupgrade**:

```sh
ubus call system board
sysupgrade -T /tmp/immortalwrt-...-xiaomi_redmi-router-ax6000-stock-squashfs-sysupgrade.bin
```

`sysupgrade -T` проверяет образ и не прошивает его. Перезапуск, прошивка,
выбор разделов и сохранение старых настроек выполняются владельцем вручную.
Команды записи flash здесь намеренно не задаются без проверки конкретного
загрузчика и состояния разделов. Проверка файлов не подтверждает загрузку,
Ethernet, Wi-Fi или аппаратный NAT на физическом устройстве.

## После ручной установки

Сначала проверить Ethernet, Wi-Fi и точный `opkg status kernel`, затем выполнить
**на самом роутере от root**:

```sh
ax6000-install-feed
```

Команда не принимает аргументов и не устанавливает пакеты. Она проверяет ABI,
архитектуру, закреплённый fingerprint ключа и подпись индекса, затем выполняет
`opkg update`. До подключения matching feed другие источники пакетов в образе
не активированы; доверенный ключ уже включён в образ.

Installer сохраняет `/etc/opkg.conf` и `/etc/opkg/*.conf` с permissions в
уникальном `/etc/opkg/ax6000-feed-backup.*`; путь выводится как `Backup:`.
Каталог backup не загружается opkg. Затем другие активные feeds отключаются;
настройки проверки подписей, архитектур и destinations сохраняются. Повторный
запуск не добавляет дубликатов. Symlink-конфигурации требуют ручного разбора:
installer откажется до изменения ключей или feeds.

Если `opkg update` завершился ошибкой, успешная настройка не заявляется.
Проверить сеть и matching feed; при необходимости исходные конфигурации
доступны в `original` указанного backup. Не подключать moving official feeds
параллельно: у opkg нет приоритета источников, и они могут предложить модули
с другим ABI или несовместимые библиотеки. Не подменять зависимость `kernel`
и не устанавливать модули принудительно.

## Tailscale и место в flash

Tailscale отсутствует **и в initramfs, и в постоянном rootfs** нового набора,
но IPK остаётся в подписанном feed и обновляется. Его официальные ARM64 ELF
при упаковке не изменяются. Наличие пакета в feed не означает, что он
помещается в текущую разметку.

На stock раздел UBI root имеет всего **80 MiB**. Пакет Tailscale 1.104.2-r2
требует около **69,2 MiB после распаковки**, сверх места, занятого остальной
системой и служебными данными UBI/overlay. Поэтому штатного свободного места
для него недостаточно. Не выполнять установку Tailscale на stock без
отдельно подготовленного достаточного хранилища.

Проверка на уже установленной постоянной системе:

```sh
df -h /overlay
opkg info tailscale
```

Это информационные команды. Их вывод нужно оценивать вместе с расходом
места зависимостей и overlay; они не являются автоматическим разрешением
на установку.

План восстановления без нажатия кнопок описан в [инструкции для стенда](TESTBENCH.md).

## Другие разметки и линии

Ubootmod выделяет UBI около **122,5 MiB**. Это иной загрузчик и разметка,
переход на которые возможен только как отдельная ручная работа владельца.
Больший раздел не гарантирует достаточный overlay или успешную установку;
такое изменение и физические испытания здесь не выполнялись.

Каждая линия имеет свой ABI и SDK. Recommended:
`6.12.108~942ed17ba3e2c90bc1373619dd44dedc-r1`,
SDK `6ef19743b104b7f2de0c3d3dffb91b3b782222cc60184ea0cc294fa653d39426`.
Latest: ABI `6.12.112~d405163bfdb42254c245797a894994c0-r1`, SDK `0b124970784803d24235d999ba77862919f651496283f4b865264bbebd575fbd`.
Модули разных линий и Linux 6.6 не взаимозаменяемы.

Latest предназначена для отдельного испытания: имеются upstream-сообщения
о регрессиях аппаратного NAT на NETSYS_V2. Успешная сборка не доказывает
работоспособность HNAT на AX6000. Регрессия может затрагивать и обычную
работу маршрутизатора; пригодность latest для этого режима ещё не подтверждена.
Проверить WAN/LAN, Wi-Fi, NAT, VPN, PBR и MultiWAN до использования
производственного трафика. Linux 6.18 отложен до появления полного
vendor-порта для AX6000.
