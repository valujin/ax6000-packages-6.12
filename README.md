# Redmi AX6000: recommended ImmortalWrt 25.12 / Linux 6.12

Развивается **только recommended** на закреплённых исходниках
[chasey-dev ImmortalWrt 25.12](https://github.com/chasey-dev/immortalwrt-mt798x-rebase),
commit `ae65e1de69971b5a2e3cf7e39390ee93f274d488`, с APK v3.
Новые сборки и ежедневные обновления latest и Linux 6.6 прекращены.
Их прежние подписанные Releases сохраняются как история; указатель старого
latest OPKG не означает продолжение поддержки этой линии.

**ASU отключён. Новая нативная прошивка собрана без ASU:** без `auc`,
`owut`, `attendedsysupgrade-common`, LuCI-приложения и переводов ASU, его JS,
ACL, конфигурации, cohort-файла и startup-скрипта. Отсутствие проверяется
в нативном банке пакетов и фактических файловых системах образов.
Новое поколение опубликовано и его подписанный APK-репозиторий активирован.
Ранее выпущенные прошивки и их SDK не переписываются. Установка выполняется
вручную с проверкой разметки и подписанного каталога.

Поколение `redmi-ax6000-612-recommended-ae65e1de6997-2c5f0d54ae97` доступно в

Образы, контрольные суммы и SDK относятся к одному подписанному поколению;
публичный feed recommended соответствует ему. SHA-256 stock sysupgrade:
`699bbc26d5e60f3075f49ebd381323717bc8f7db7065307e86d2ede6be85e49a`.

## Состав и разметки

Сохраняются **stock, mtkuboot и ubootmod**, нативный stock factory UBI,
SDK, банк kmods, AmneziaWG, WireGuard, PBR/LuCI автора MOSSDeF,
vendor Wi-Fi и ручной выбор страны `DB` в LuCI.
В закреплённом recommended используется **mt_wifi 7.6.7.3**
(`CONFIG_MTK_MT_WIFI_DRIVER_VERSION_7673=y`). Выбор `DB` не меняет страну
по умолчанию, не форсирует мощность и не отключает DFS.

**Tailscale отсутствует в initramfs и постоянном rootfs всех трёх разметок.**
Он доступен отдельным APK в feed. Компактная версия 1.104.2-r3 содержит один
ARM64 `tailscale.multicall`, UPX и две ссылки `tailscale`/`tailscaled`;
опубликованный APK — **11 921 395 байт**, Installed-Size — **12 225 198 байт**.
Это результат SDK/QEMU-проверок, без утверждения об аппаратном тестировании
пакета. Историческая r2 с двумя static-бинарниками занимала около 69,2 MiB
после распаковки.

Разметки не взаимозаменяемы. [Инструкция по прошивке](docs/FLASH.md)
объясняет различие factory UBI, FIT для RAM и sysupgrade.
Не применять mtkuboot/ubootmod к stock и не менять загрузчик автоматически.
Другие разметки и HNAT на физическом устройстве в этом испытании не проверялись.

## MediaTek EasyMesh

Новый рецепт включает проприетарный стек MediaTek Mesh и страницу
**Сеть → MediaTek Mesh** с русским переводом: основной роутер/дополнительный
узел, кабель/Wi-Fi, сопряжение, состояние служб и восстановление Wi-Fi
при отключении. Mesh по умолчанию выключен. Все узлы должны использовать
новую согласованную прошивку; установка только пакетов в старый образ
не поддерживается. [Подготовка узлов и ограничения](docs/MEDIATEK-MESH.md).
На одном AX6000 со штатной разметкой финальный образ загрузился; проверены
страница Argon, включённые радиомодули 2,4 и 5 ГГц со смешанным WPA2/WPA3,
WAN и DNS. Через LuCI проверены запуск контроллера, окно сопряжения PBC и
выключение с восстановлением настроек; элементы управления также проверены
на узком экране. На финальном образе того же устройства проверено восстановление
беспроводного агента при отсутствии контроллера: исходный LAN-адрес,
радиомодули, DHCP и IPv6-службы вернулись после неудачного подключения.
Клиентский трафик на финальном образе, подключение двух устройств,
сопряжение и роуминг ещё не проверены.

## Пакеты

[Подписанный feed recommended](https://valujin.github.io/ax6000-packages-6.12/)
сохраняет точный kernel ABI, архитектуру и ключ своего поколения.
В совпадающей прошивке проверить ядро и подключить feed **на роутере от root**:

```sh
apk --no-network query --installed --format json --fields name,version kernel
ax6000-install-feed
apk update
```

Для старых образов исправление встроенного установщика описано в
[исторической инструкции](docs/ASU-CLIENT-HOTFIX.md).
Установщик проверяет подпись, ключ, архитектуру и ABI, сохраняет настройки;
он не устанавливает Tailscale или другие приложения. Для нужного Tailscale:

```sh
apk add tailscale
```

Согласованные userspace-feeds ImmortalWrt 25.12 base, luci, packages,
routing и telephony доступны с тегом `@public`, например `apk add tree@public`.
Kernel, vendor-стек и защищённые зависимости закреплены на нативных версиях.
Не подменять зависимость `kernel` и не смешивать модули разных поколений.
Перед установкой проверить свободное место в overlay и зависимости.

## Сборка и обновления

Экспериментальные сборки выполняются на собственном сервере из
`profiles/redmi-ax6000-612-recommended-new.json`: все три разметки, factory,
SDK и фактическая нативная проверка. Затем в отдельном рабочем каталоге
проверяется сборка пакетов через полученный SDK. Исходники, журналы и результаты
проверок сохраняются. GitHub используется для подписи, хранения Release
и публикации feed; компиляция прошивки и SDK-пакетов в этом процессе локальная.
[Порядок локальной сборки и публикации](docs/LOCAL-PUBLICATION.md).

Ручной путь через `firmware.yml` и `publish-firmware-generation.yml`
сохранён как отдельная возможность; текущие экспериментальные сборки
его не используют. [Описание этого пути](docs/PUBLISH-GENERATION.md).
Затем оператор активирует поколение через
`publish-existing.yml`, указав `channel=recommended`, точный `release_tag`
и `replace_build_id` текущего подписанного поколения. Новый generated profile
копируется из фактического RAW, а не составляется вручную.
Замена сохраняет закреплённые исходники, Linux kernel ABI, архитектуру,
разметки и ключ. Допускаются удаление ASU, согласованный набор MediaTek Mesh
и новая идентичность реальной сборки/SDK. Vendor-драйвер и демоны Mesh
проверяются и поставляются вместе в новом поколении.

Ежедневно в 03:17 UTC мониторятся feeds, stable Tailscale, согласованная пара
PBR/LuCI и рецепт AmneziaWG. Автоматическая компиляция SDK-пакетов на GitHub
по умолчанию выключена: публикация нового поколения сама её не включает.
На время испытаний Mesh обновления собираются и публикуются с собственного
сервера по описанному выше процессу; автоматический локальный планировщик
пока не настроен. Отдельная переменная репозитория `AX6000_HOSTED_SDK_BUILDS=true`
разрешает прежний hosted-путь только при явном выборе оператора.
Нативное ядро, kmods и защищённые зависимости сохраняются; сбой не заменяет
последний подписанный feed. Обновление kmods требует отдельно проверенного
нового нативного поколения.

Исторические ASU-каталоги, проверки и инструкции в `docs/` относятся к ранее
выпущенным образам. Они не являются частью нового процесса сборки и установки.
